Container Management API for podman containers.

A project sprung out of the urge to learn rust and wanting to build a API for managing podman containers in my local environment.

All requests and responses are JSON based for all API endpoints.

All interfaces related to systemwide information and configuration for podman resides under here.

/v1/common/postEnvFileCreate

Create or replace an env file with parameters used in containers, good for moving variables like usernames, passwords and so on from the create command when creating a container.

The file will automatically get the .env added at the end, so the name tag should only contain the name you want to give it.

the content data must be separated with a | in order for the API to successfully split the data into correct format, there are no need to add an | after final variable.

For example:

{
  "name": "filename",
  "content": "USER=user|PASS=password",
  "replace": "no"
}

You can overwrite an existing file by setting the replace tag to yes, otherwise it will not do anything if the file already exists. The replace tag can only consist of the words yes or no, if you put something else here it will halt and error out.

for example:

{
  "name": "filename",
  "content": "USER=user|PASS=password",
  "replace": "yes"
}

BasicAuth

string
content
string
replace

/v1/common/postSecretCreate

Create or replace a secret with information used in containers, good for moving variables like usernames, passwords and so on from the create command when creating a container.

During the creation or replacement of a secret a temporary file is placed under the folder assigned in the configuration file. This file will automatically get the .tmp added at the end and the file should be removed automatically when operation is successful.

the data tag is sent in as is into the secret so be sure to format it correctly before it is processed.

For example:

{
  "name": "secretname",
  "content": "MySecretPassword",
  "labels": "<label1>=<string>,<label2>=<string>",
  "replace": "no"
}

You can overwrite an existing secret by setting the replace tag to yes, otherwise it will not do anything if the secret already exists. The replace tag can only consist of the words yes or no, if you put something else here it will halt and error out.

for example:

{
  "name": "secretname",
  "content": "MyNewSecretPassword",
  "labels": "<label1>=<string>,<label2>=<string>",
  "replace": "yes"
}
Authorizations:
BasicAuth
Request Body schema: application/json

string
data

/v1/common/deleteEnvFile

Remove an ENV file from the server when it is not needed anymore.

To remove a ENV file a security key must be provided or it will not let you delete the file.

The name of the file to delete is written without .env, this is added automatically when doing the request.

For example:

{
  "name": "name",
  "key": "secretkey"
}
Authorizations:
BasicAuth

Responses

/v1/common/deleteEnvFile

Response samples

  • 200
  • 400
Content type
application/json
{
  • "Code": "200",
  • "Name": "<string>",
  • "State": "Deleted"
}
